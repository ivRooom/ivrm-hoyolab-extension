# ivRooom HoYoLAB Link

ログイン中の HoYoLAB セッションを [ivRooom ポータル](https://member.ivrm.jp) へワンクリックで連携するブラウザ拡張です。連携すると、原神の樹脂やスターレイルの開拓力といったリアルタイム情報がポータルのゲームタブに表示されます。

HoYoLAB には公式の OAuth / API キーがないため、ポータルへの登録は通常「開発者ツールで Cookie を取り出して貼る」手順が必要です。この拡張はその手順をなくすためのものです。

あわせて、拡張の中だけで完結する任意機能として、HoYoLAB デイリーチェックインの自動受取とギフトコードの自動交換、アークナイツ：エンドフィールド（Skport）のデイリーチェックイン自動受取と理性（スタミナ）表示があります（後述）。

## 使い方（はじめての方向け）

1. GitHub の Release ページから最新の zip をダウンロードして展開します
2. Chrome で `chrome://extensions` を開き、デベロッパーモードを ON にして、「パッケージ化されていない拡張機能を読み込む」から展開したフォルダを選びます
3. ブラウザで [HoYoLAB](https://www.hoyolab.com) にログインします
4. ポータルのプロフィールでペアリングコードを表示し、拡張のポップアップに貼って「連携する」を押します
5. （任意）ポップアップの「自動チェックイン・コード交換」をオンにすると、チェックインとギフトコードの交換が自動になります

報酬は各ゲーム内のメールに届きます。

## 使い方

1. ブラウザで [HoYoLAB](https://www.hoyolab.com) にログインしておく
2. ポータルのプロフィール（HoYoLAB連携）で「ペアリングコードを表示」を押す
3. この拡張のポップアップにコードを貼って「連携する」を押す

ペアリングコードはポータルが発行する10分だけ有効な署名つきトークンで、連携できるのは発行した本人のアカウントだけです。

## セキュリティ

- 読む Cookie は HoYoLAB の `ltuid_v2` / `ltoken_v2` / `ltmid_v2`（ペアリング連携用）と、Skport の `ACCOUNT_TOKEN`（エンドフィールドの自動チェックイン用、その場で公式 API のセッション資格情報に交換し、値も資格情報も保存しない）です
- ペアリング連携の送信先は `https://api.ivrm.jp/hoyolab-pairing/exchange` のみです
- ペアリング連携そのものは情報を保存しません。保存するのは下記の自動機能の設定・交換履歴・実行ログだけで、いずれもこのブラウザの中（`chrome.storage.local`）に閉じています
- ポータル側では Cookie は暗号化して保存され、連携解除で即時削除されます
- 権限は `cookies` / `alarms` / `storage` / `notifications`（ログイン切れの通知用）と、hoyolab.com / hoyoverse.com / api.ivrm.jp / hoyo-codes.seria.moe / skport.com / as.gryphline.com へのホスト許可です

## 自動チェックイン・コード交換（任意機能・既定オフ）

ポップアップの「自動チェックイン・コード交換」でオンにすると、このブラウザの HoYoLAB ログインを使って次を自動で行います。ポータルは一切関与しません。

- **デイリーチェックイン**: 毎日 01:05（JST）に原神／崩壊：スターレイル／ゼンレスゾーンゼロのチェックインを受け取ります。Chrome が閉じていた場合は、次回起動時に未受取分を取り戻します
- **ギフトコード交換**: 3時間ごとに [hoyo-codes](https://github.com/seriaati/hoyo-codes) の公開 API で新しいコードを確認し、未交換のものを公式の交換 API で交換します。交換済みのコードは記録して再送しません。ゼンレスゾーンゼロの「同じ種別（接頭辞）では1つだけ交換できる」コードは、1件交換できたら残りを対象外にします
- **制御**: マスタースイッチとゲーム別のオン／オフ（後述）、「今すぐ実行」、実行ログと交換件数の表示があります
- **安全側の挙動**: 公式側でパズル認証（リスクコントロール）が必要になったら自動処理を止めて、公式ページでの手動操作をお願いする表示にします。ログインが切れているときはチェックインを行いません
- **取りこぼし対策**: 時間どおりに実行できなかったり一時的に失敗したりしたチェックインは、その日のうちに約2時間おき（最大4回まで）自動で再試行します。ログインが切れていることに気づいたら、拡張アイコンに「!」バッジを出し、通知とポップアップのバナーで1回だけお知らせします（ログインし直して実行が成功すると自動で消えます）
- **ポータルへのログイン状態の報告（連携済みの場合のみ）**: ポータル連携をしているときは、ログイン状態の変化（切れた／直った）だけをポータルへ知らせます。対象の希望者には専用チャンネルでお知らせが届きます。送るのは「どのサービスが・切れたか直ったか」だけで、Cookie やログイン情報そのものは送りません

この機能は HoYoLAB のセッション Cookie の値を読んだり保存したりしません。ブラウザが公式ドメインへ通常送るログイン状態をそのまま使います。

なお、この自動化は HoYoverse 公式の提供機能ではなく、公式はサードパーティ製ツールについて利用規約上の注意を公表しています。使うかどうかはアカウント本人の判断で、既定はオフです。

## エンドフィールド（Skport）対応（任意機能・既定オフ）

同じマスタースイッチ配下で、アークナイツ：エンドフィールドの Skport デイリーチェックインも自動化できます。ブラウザで [Skport](https://game.skport.com/endfield/sign-in) にログインしておくことが前提です。

- **デイリーチェックイン**: 毎日 05:05（JST）に受け取ります（エンドフィールドの日次リセットはアジアサーバーで 04:00（UTC+8）のため、その直後）。受け取り前に公式 API で当日の受取状況を確認し、受取済みなら何もしません。Chrome が閉じていた場合は、次回起動時に取り戻します
- **理性（スタミナ）表示**: ポップアップに現在の理性と満タンまでの目安を表示します。自動チェックインのついでに更新されるほか、「理性を更新」ボタンでも取得できます（こちらは自動化がオフでも使えます）
- **認証の仕組み**: Skport のログイン Cookie（ACCOUNT_TOKEN）を読み、Gryphline の OAuth でセッション資格情報（cred / signToken）に交換して、リクエストごとに署名して公式 API を呼びます。Cookie の値も資格情報も保存しません

こちらも Gryphline 公式の提供機能ではなく、利用規約上の位置づけは HoYoLAB の自動化と同じグレーゾーンです。使うかどうかはアカウント本人の判断で、既定はオフです。

## ゲームごとの設定（表示／自動）

ポップアップのゲーム一覧では、ゲームごとに2つのスイッチを切り替えられます。

- **表示**: オフにしたゲームはポップアップの状況表示から消え、自動処理の対象からも外れます
- **自動**: そのゲームの自動チェックイン（と HoYoLAB のコード交換）を有効にするかどうかです

既存の設定（タイトル別のオン／オフ）は初回に自動で引き継がれます（従来のスイッチが「自動」側に入り、「表示」は全ゲームオンから始まります）。

## 対応ブラウザ

Chrome / Edge（Manifest V3）。Firefox は後続対応予定です。

## 開発

依存パッケージはありません。テストは Node 標準の test runner で動きます。

```sh
npm test
```

### 手元で読み込む（開発版）

1. Chrome で `chrome://extensions` を開き、デベロッパーモードを ON
2. 「パッケージ化されていない拡張機能を読み込む」でこの repo のルートを選ぶ

### 構成

- `manifest.json` — MV3 マニフェスト
- `src/popup.html` / `src/popup.css` / `src/popup.js` — ポップアップ UI
- `src/background.js` — 自動機能のスケジュール実行（service worker、chrome.* の配線のみ）
- `src/lib/hoyolab-cookie.mjs` — Cookie の選択・整形と応答解釈（純粋関数、テスト対象）
- `src/lib/hoyolab-auto.mjs` — 自動機能のゲーム定義・応答分類・冪等管理・スケジュール判定（純粋関数、テスト対象）
- `src/lib/hoyolab-auto-runner.mjs` — 自動機能の実行フロー（依存注入でテスト可能）
- `src/lib/game-settings.mjs` — ゲームごとの表示／自動設定と旧設定からの移行（純粋関数、テスト対象）
- `src/lib/skport.mjs` — Skport の署名（HMAC-SHA256→MD5）・応答解釈・理性抽出・スケジュール判定（純粋関数、テスト対象）
- `src/lib/skport-runner.mjs` — Skport の OAuth 交換・チェックイン・理性取得の実行フロー（依存注入でテスト可能）
- `test/` — `node --test` のユニットテスト
